## 1. 目标与边界

### 1.1 一周目标

做出一门课、一条闭环、能录成 5 分钟视频的原型：

```
进入课程 → 开始诊断（10—12 题）
        → 雷达图 + 薄弱单元 Top3
        → 7 天计划 → 复测
        →（可选）1 道开放题评分 → 模拟教师改分
```

不追求“效果已经很好”，只追求“流程真的跑通、数字真的能复现”。

### 1.2 一周不做

- 真实用户访谈、真实教师盲评、真实课程授权
- 真实学习增益、前后测对比
- 教师班级热力图、多学生管理后台
- 实验室模块（原题里的 AI 通识实验室）、多套自动组卷
- 多课程、多语言、登录、移动端
- 微调、多智能体、LangChain
- 任何伪造的“教师评分/教师标注/学习提升”

### 1.3 决赛前一个月再做

- 如果能拿到 1 位教师 + 5—10 位学生：做小试点、收反馈、补真实指标
- 如果拿不到：保持“模拟数据、仅验证流程”的声明，不编效果
- 补申报表、PPT、视频、README、三次排练

> 7 天只负责“有东西可演示”；一个月负责“尽量有真实反馈”。

## 2. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| UI | Streamlit | 一人最快出页面 |
| LLM | DeepSeek `deepseek-flash` | 当前主力模型，40 元够用，OpenAI 兼容 |
| 检索 | BM25 + jieba | 6 份文档够用，依赖少 |
| 数据库 | SQLite（Python 自带） | 零配置 |
| 图表 | Plotly | 雷达图、柱状图 |
| 评测 | JSON + 手写脚本 | 不做大框架 |
| 开发助手 | OpenCode Go | 只辅助写代码/调试 |
| 运行 | 本地 + 录屏 | 现场网络不可控 |

**依赖只留 7 个**：`streamlit`、`openai`、`python-dotenv`、`pandas`、`plotly`、`jieba`、`rank-bm25`。  
**本周不装**：FastAPI、LangChain、Docker。  
**如果 BM25 效果差**：改 chunk、加章节过滤、换关键词，不换检索方案。

## 3. 数据

### 3.1 课程

课程名：**《深度学习》基础**（测试课程）。参考书：`reference_material/深度学习.pdf`。  
只选 6 个主题，不整本入库；具体章节号以你整理的 md 为准。

| 单元 | 参考章节 | 内容 | 知识点示例 |
|---|---|---|---|
| 1 | 第 1 章 | 引言 | 深度学习历史、表示学习、深度 |
| 2 | 第 2 章 | 线性代数 | 张量、矩阵乘法、范数 |
| 3 | 第 3 章 | 概率与信息论 | 条件概率、期望、交叉熵 |
| 4 | 第 5 章 | 机器学习基础 | 训练/测试、过拟合、损失函数 |
| 5 | 第 6 章 | 深度前馈网络 | 神经元、激活函数、反向传播 |
| 6 | 第 7/8 章 | 正则化与优化 | 权重衰减、Dropout、梯度下降 |

每单元 2—3 个知识点，共 12—18 个。先整理第 1 单元，够 D1 跑通；D2 前至少 4 份、最好 6 份；其余在 D3 前补齐。

### 3.2 文档

- **两层资料，不要混在一起**：
  - **原文层**：把 PDF 按章/页整理成 md，放 `reference_material/book_md/`，只在本机检索，不提交。
  - **摘要层**：用自己的话写 6 份教学摘要，放 `docs/course/`，每份 800—1500 字，可提交。
- 摘要必须带 `source_pages` / `source_chunk_ids`，能回到原文；**摘要不是事实源，原文才是**。
- 文档头写元数据：`doc_id`（如 `DL-CH01-01`）、`title`、`chapter`、`kp_ids`、`source`、`source_pages`。
- 不复制原书长段进仓库；答案里只引用短句，并给出页码/章节。

### 3.3 题库

- 共 30 题：12 道诊断（每单元 2 道）+ 10 道练习 + 8 道复测。
- 题型：单选、判断、简答；每题带 `chapter`、`kp_ids`、`difficulty`、`answer`、`explanation`、`source_chunk_id`。
- 诊断卷 10—12 题；复测卷 8 题，排除学生已做过的题。

### 3.4 学生记录

**学生端不做“选择身份”这一步。** 掌握度只能由答题记录算出来，不能由年级/专业/自我评价决定。

- 学生端默认当前学生 `S001`，进入后直接开始诊断。
- 数据表只保留 `students(id, display_name)`；不存年级、专业、自评水平。
- 诊断完成后，根据掌握度生成展示标签“基础薄弱/中等/较强”；标签是诊断输出，不是输入。
- `eval/` 里保留 3 条模拟记录做自检，不在学生端出现。
- 如果答辩需要对比，侧边栏折叠一个“演示数据切换”，明确标注“模拟数据”，不作为学生流程。

### 3.5 评测集

- 12 道问答：6 道 dev（调 prompt/阈值）+ 6 道 test（验收，不参与调参）。
- 3 条诊断自检记录：先人工写“预期最弱单元”，再跑诊断；不要倒过来改。
- 5 份开放题答案（如果做评分）：只做人工抽查，不算 MAE。
- `data/seed/`（演示）与 `eval/`（验收）分开放，避免拿演示数据当评测数据。

## 5. 核心逻辑

### 5.1 课程问答

- 建立两层索引：摘要层（`docs/course`）和原文层（`reference_material/book_md`）。
- 按 Markdown 标题切分，每段 400—600 字，重叠 50 字；chunk 带 `layer`、`page`、`chapter`。
- 检索：摘要 top2 + 原文 top3；合并去重；原文用于事实校验。
- 不把整本书塞进 prompt：一次只送 5 个片段（约 2000—3000 字）；跨章问题按章拆。
- Prompt：摘要用于组织讲解，**事实以原文为准**；冲突时引用原文；每条结论标 `[S1]`（摘要）或 `[O1]`（原文）。
- 引用校验：去掉标点/空格后，引用句必须能在对应 chunk 中找到；原文层找不到支持，就降级为“仅摘要，未核对原文”或直接拒答。
- 如果原文层不可用（比如换电脑没带 PDF），只用摘要层时要明确提示“未核对原文”。
- 用 6 道 dev 题调一个保守阈值；宁可拒答，不要自由发挥。

### 5.2 自动组卷

- `build_quiz(unit_ids, n, exclude_ids)`：按单元/难度抽题，排除已做题。
- 诊断卷 10—12 题；复测卷 8 题。
- 这是 A2 任务里“自动组卷”的最小实现，不需要单独做复杂系统。

### 5.3 学情诊断

- 只做**单元级**掌握度，不做 30 个 KP 的精细诊断。
- `mastery = Σ(答对 × 难度) / Σ(难度)`，难度权重 1/2/3；不做时间衰减，保持可解释。
- 单元权重 1—3，按课时/考核占比在 `data/seed/units.json` 预设；同分时权重高的排前面。
- 某单元答题数 < 2：标“数据不足”，不强行进 Top3。
- 薄弱 Top3：在答题数 ≥2 的单元里按 mastery 升序；同分按单元权重降序。
- 每个薄弱点必须带证据：错题 ID、学生答案、正确答案。
- 掌握度只由 `attempts` 计算；年级/专业/自评标签不参与计算。

### 5.4 个性化 7 天计划

- 取薄弱单元 Top2（不是 Top3，7 天更现实）。
- 每单元配：1 段讲义 + 2 道练习 + 1 个总结任务。
- 铺满 7 天，每天 20—30 分钟；第 7 天复测 8 题。
- 计划结构由规则生成；LLM 只负责润色任务描述。LLM 挂了计划也能出。
- 验收只看：7 天都有任务、覆盖 2 个薄弱单元、题目不重复、每天 ≤30 分钟。

### 5.5 开放题评分（可选）

- 1 道题、4 维 rubric（准确性/完整性/逻辑/表达）、1 次 LLM 调用。
- 每维输出分数、理由、学生原话证据；证据必须能在答案中原文匹配。
- 教师可改总分，记录原分/新分/理由/时间；演示时由你扮演教师，页面标注“模拟教师改分”。
- 不做 3 次取中位数，不报 MAE；只做 5 份人工抽查。
- **D5 中午还没跑通就砍掉**，不要让评分阻塞主演示。

### 5.6 路由与 Agent

- 侧边栏按钮：问答 / 诊断 / 计划 / 评分；聊天框里用关键词路由兜底。
- 工具就是普通 Python 函数：`search_course`、`get_attempts`、`diagnose`、`make_plan`、`grade_answer`。
- 最多 4 步工具调用；trace 记录工具名、参数、耗时；不展示内部思维链。
- 对外说“工具调用型助教”，不说“自主智能体”。

### 5.7 输出与 Prompt

- 诊断/计划/评分要求 JSON；`json.loads` 失败重试 1 次。
- 问答 temperature 0.2；评分/诊断 0；`max_tokens` 600—800。
- Prompt 放 `prompts/`，随代码一起 commit，便于回滚。

**D5 之后不加新功能。** 新想法写进 backlog，不碰主路径。

## 7. LLM 使用规则

| 交给 LLM | 自己写 / 必须看懂 |
|---|---|
| Streamlit 布局、Plotly 配置 | chunking、BM25 评分、引用校验 |
| OpenAI SDK 包装、重试 | 诊断公式、薄弱点排序 |
| SQL 建表、CRUD 样板 | 7 天计划规则、题目抽取 |
| 报错解释、单元测试草稿 | 数据清洗、评测脚本、指标口径 |

具体规则：

1. 先自己写函数签名、输入输出、预期结果，再让 LLM 补实现。
2. 每次只改一个函数/一个文件，要求“最小可运行补丁”，不要整项目重写。
3. 生成后先跑，再让 LLM 逐段解释；解释不了就不 commit。
4. 默认拒绝新框架；能用 stdlib/现有依赖就不加。
5. 卡住超过 30 分钟，给 LLM：报错 + 最小复现代码 + 预期/实际；让它给 2 个假设，不要直接重写。
6. LLM 不生成课程事实、不生成指标数字；数据和数字自己核对。
7. 每天 `NOTES.md` 写 3 行：学会了什么 / 哪里还不懂 / 明天第一件事。
8. 每周回看一次：哪些代码是自己写的，哪些是抄的；抄的部分能否独立改出来。

## 8. DeepSeek 40 元怎么花

- 只用 `deepseek-flash`，不用 `deepseek-reasoner`（已退役）；`max_tokens` 600—800。
- 问答只送 top3 chunk，不送整份文档；演示问题答案做缓存。
- 不做 3 次评分、不批量生成题库；30 题自己整理，LLM 只帮忙润色/查错。
- 40 元对“开发期几十次 + 评测一百次左右”足够，以实际账单为准。
- OpenCode Go 只用于写代码/调试，不接进应用；应用只读 `DEEPSEEK_API_KEY`。
- 预算紧张时：缓存演示答案、缩短 prompt、减少评测调用。
- BM25 是本地计算，没有额外 API 费用。

## 9. 评测与说法

| 指标 | 样本 | 目标 | 说明 |
|---|---|---|---|
| 检索 hit@3 | 12 题（6 dev / 6 test） | test 6 题中 ≥4 题命中 | 小样本自检，不冒充学术评测 |
| 引用抽查 | 8 条回答 | ≥7 条引用能支持结论 | 人工看，不只看字符串匹配 |
| 摘要-原文一致性 | 6 份摘要 | ≥5 份无事实冲突 | 逐段对照原文；冲突以原文为准 |
| 原文引用正确率 | 8 条回答 | ≥7 条能回到原文页码/段落 | 人工抽查 |
| 诊断自检 | 3 条模拟记录 | ≥2/3 最弱单元命中预期 | 预期先写、再看诊断；不看 Top3 重合，6 单元下随机重合太高 |
| 响应时延 | 5 次调用 | 平均 <15 秒 | 记录时间，不承诺峰值 |
| 评分抽查（可选） | 5 份答案 | ≥4 份无明显错误 | 不报 MAE，不称“教师一致” |

写报告时只写这些，不写“学习提升 24%”“教师评分一致”。  
所有数字后面加一句：**“模拟数据/开发者自检，仅验证流程，不构成真实教学效果证据。”**

README 必须写“已知限制”：

- 模拟学生、模拟答题记录
- 无真实用户、无教师盲评
- 样本量小，指标只作自检
- 7 天计划未经过真实 7 天执行
- 决赛前若拿到试用，再补真实数据

**不要写**：“已获教师采用”“学生试用后提升”“教师评分一致性 0.8”。现在没有这些数据。

答辩 Q&A 准备 8 个：

1. **和 ChatGPT 有什么区别？** 课程资料 grounding、强制引用、单元诊断、7 天计划、教师可改分。
2. **幻觉怎么处理？** 检索不到就拒答；引用句原文校验；没有有效引用就降级。
3. **没有真实用户，怎么证明有效？** 不证明学习效果；7 天只证明流程可跑、指标可复现；决赛前争取小试点。
4. **一个人一周怎么做得完？** 砍掉双进程/教师后台；BM25+Streamlit 单体；LLM 只辅助写代码。
5. **数据合规吗？** 自建/公开资料、模拟学生、不连校内系统、密钥不入库。
6. **为什么不用向量库？** 6 份文档约 30 个 chunk，BM25 足够；向量库会增加依赖，不是当前必需。
7. **为什么选《深度学习》？** 有现成结构，适合做一门课的 grounding；只选 6 个主题，不整本入库，避免范围失控。
8. **摘要会不会偏差？** 会，所以摘要只做教学层；事实以原文层为准，答案给原文页码，并抽查摘要-原文一致性；冲突时改摘要或拒答。

一句话答辩稿：

> 我们做的不是通用问答，而是一门课的带证据 AI 助教：答案引原文、诊断引错题、计划按薄弱点生成。7 天完成可演示原型；真实教学效果在决赛前通过小范围试点验证，不用模拟数据冒充效果。

## 12. 风险与砍法
